`KAGE-MAN.DOJO` هو ميدان تدريب كامل وقابل للعمل دون إنترنت على إطار عمل
Metasploit. جهاز Ubuntu افتراضي واحد يستضيف ثلاثة قطاعات macvlan — «حافة
إنترنت» WAN، ومنطقة منزوعة السلاح DMZ، وشبكة داخلية INTERNAL — مُعبّأة بـ 26
تطبيقًا مصابًا منتقى. يبدأ المتدرب من جهاز Kali متصل بقطاع **WAN فقط**، فيخترق
الخدمات المواجهة للإنترنت، ثم يعبر محورًا مزدوج الاتصال إلى الـ DMZ، ثم يعبر
مفصلًا ثانيًا إلى الشبكة الداخلية، وينهي بامتحان *استمرارية* (persistence) تبقى
فيه حمولات `msfvenom` حيّة بعد إعادة التشغيل.

تمتد الدورة على ثلاثة أحزمة في حملة واحدة:

| النموذج | الحزام | ما تتدرب عليه |
|---|---|---|
| 1 | أبيض | سطح هجوم WAN + الباب إلى الـ DMZ: وحدات جاهزة (`use`/`set`/`run`) |
| 2 | بنّي | الإعداد والتسلسل والوصول عبر الوحدات المساعدة — بما في ذلك مفصل DMZ→INTERNAL |
| 3 | أسود | استغلال يدوي + سير عمل كامل `msfvenom` ← handler ← post (بما فيه ترحيل JNDI) |
| 4 | — | إتقان المحور: autoroute, socks, portfwd، والترحيل العكسي عبر المحور |
| 5 | **التتويج** | **الاستمرارية:** حمولات ويب، حسابات خلفية، مفاتيح SSH، خدمات systemd/cron — مُتحقَّق منها بعد إعادة تشغيل حقيقية |

كل ما تحتاجه موجود داخل هذا المستودع: مصادر المعامل مُضمَّنة تحت
[`vulhub/`](vulhub/)، وملفات compose مُولّدة (ومُودعة) بمسارات **نسبية**،
والأدوات مجرد شِل + `make`. نسخة جديدة تعمل كما هي.

| | |
|---|---|
| اسم المضيف | `KAGE-MAN` (الاسم الكامل `kage-man.dojo`) |
| نوع الميدان | 3 قطاعات macvlan · 26 معملًا · مصادر معامل مُضمَّنة |
| النظام/المنصة | جهاز Ubuntu 20.04 على VirtualBox، مضيف Docker |
| العناوين | `.250` على كل قطاع (`192.168.80.250`، `172.16.80.250`، `10.0.8.250`) |
| القطاعات | WAN `10.0.8.0/24`، DMZ `192.168.80.0/24`، INTERNAL `172.16.80.0/24` |
| مصدر الحقيقة | [`labs.manifest`](labs.manifest) + [`segments.conf`](segments.conf) |

## البنية

جهاز VirtualBox واحد بثلاث بطاقات شبكة، واحدة لكل قطاع. كل بطاقة هي **الواجهة
الأمّ** لشبكة Docker من نوع macvlan، فيصبح كل حاوية معمل عضوًا كامل العضوية في
قطاعه — بعنوان MAC وIP خاصّين، **دون أي ربط منافذ على المضيف**. يقرأ
[`scripts/gen-labs.sh`](scripts/gen-labs.sh) ملف
[`labs.manifest`](labs.manifest) ويُصدر ملف compose مستقلًا لكل معمل.

```text
          VirtualBox NAT networks (L2 + outbound NAT)
   KAGE-DOJO-WAN           KAGE-DOJO-DMZ            KAGE-DOJO-INT
     10.0.8.0/24           192.168.80.0/24          172.16.80.0/24
         │                       │                        │
    ┌────┴───────────────────────┴────────────────────────┴────┐
    │ KAGE-MAN — Ubuntu VM / Docker host · host .250 on each seg │
    │   macvlan KAGE-DOJO-WAN  ← internet edge (7 services)      │
    │   macvlan KAGE-DOJO-DMZ  ← 11 targets + the pivot seam     │
    │   macvlan KAGE-DOJO-INT  ← 8 targets + persistence host    │
    └───────────────────────────────────────────────────────────┘
         ▲
   student Kali (WAN)  ──▶ foothold ──▶ seam ──▶ INTERNAL
```

### القطاعات وبطاقات الشبكة

| القطاع | شبكة Docker | عنوان المضيف | الشبكة الفرعية | البوابة | المسار الافتراضي |
|---|---|---|---|---|---|
| DMZ | `KAGE-DOJO-DMZ` | `192.168.80.250` | `192.168.80.0/24` | `192.168.80.1` | **نعم** |
| INTERNAL | `KAGE-DOJO-INT` | `172.16.80.250` | `172.16.80.0/24` | `172.16.80.1` | لا (محلي) |
| WAN | `KAGE-DOJO-WAN` | `10.0.8.250` | `10.0.8.0/24` | `10.0.8.1` | لا (محلي) |

قطاع الـ DMZ وحده يحمل المسار الافتراضي؛ أما INTERNAL وWAN فمحليّان، وهذا
بالضبط ما يُجبر الحملة على أن تكون عبر محاور (pivoting) لا عبر التوجيه. وبسبب
تصميم macvlan **لا يستطيع المضيف الوصول إلى حاوياته** — تحقّق من داخل القطاع
عبر `make health` / `make smoke` لا عبر `curl` من المضيف.

## البناء بأمر واحد (Vagrant)

من مضيف فيه **VirtualBox + Vagrant**، أمر واحد يفعل كل شيء. راجع
[`INSTALL_AR.md`](INSTALL_AR.md) لدليل التثبيت الكامل.

```bash
./install.sh            # يتحقق من متطلبات المضيف ثم ينفّذ vagrant up
vagrant ssh             # ثم، داخل الجهاز:
cd /opt/kage-man
make ps                 # ما الذي يعمل  (make down LAB=<name> للإيقاف)
```

على **ويندوز** استخدم مُغلِّف PowerShell:

```powershell
.\install.ps1           # أو: powershell -ExecutionPolicy Bypass -File .\install.ps1
.\install.ps1 -NoStart  # -Gui | -Provision | -Destroy
```

افتراضيًا يقوم `vagrant up` (و`./install.sh`) **ببناء وتشغيل كل المعامل** إضافة
إلى خادم DNS لقطاع WAN، وكلّها بسياسة `restart=unless-stopped` لتبقى بعد إعادة
التشغيل. هذا يتطلب ذاكرة وقرصًا كافيين، فكبّر الجهاز أو قلّل العمل عبر
`KAGE_START`:

```bash
KAGE_START=none  vagrant up          # التهيئة فقط — دون بناء أو تشغيل المعامل
KAGE_START=build vagrant up          # بناء كل الصور دون تشغيلها
KAGE_MEMORY=12288 KAGE_CPUS=6 vagrant up   # جهاز أكبر (الافتراضي 8192MB / 4 vCPU)
```

اسم الجهاز في VirtualBox هو **`KAGE-MAN.DOJO`**. الدخول من الطرفية باسم
المستخدم **`vagrant`** وكلمة المرور **`vagrant`** (مع `sudo` بلا كلمة مرور)؛
أما `vagrant ssh` فيستخدم المفتاح المُولَّد ولا يحتاج كلمة مرور.

يعمل الجهاز **بلا واجهة** افتراضيًا. لفتح نافذة VirtualBox — ورؤية شعار الدوجو
كشاشة إقلاع — شغّله بواجهة رسومية:

```bash
KAGE_GUI=1 vagrant up        # أو: vagrant reload إن كان يعمل
```

### شبكات VirtualBox

القطاعات الثلاثة هي **شبكات NAT مُسمّاة في VirtualBox** تُنشَأ عبر `VBoxManage`
من `segments.conf`. يُنشئها `vagrant up` تلقائيًا، أو أنشئها بنفسك (يعمل بنفس
الطريقة على Linux/macOS وWindows):

```bash
./scripts/vbox-networks.sh create            # Linux / macOS
./scripts/vbox-networks.sh list | remove
```
```powershell
powershell -ExecutionPolicy Bypass -File scripts\vbox-networks.ps1 create   # Windows
```

**المهاجم:** اربط جهاز Kali بشبكة **`KAGE-DOJO-WAN`** بعنوان ثابت `10.0.8.x`
وامشِ في الحملة من WAN إلى الداخل.

### خادم DNS لقطاع WAN — «إنترنت مزيّف» ([`dns/`](dns/))

خادم CoreDNS على WAN (`10.0.8.53`) يجعل خدمات WAN تبدو كمواقع إنترنت حقيقية:
يجيب على الأسماء في [`dns/dojo.hosts`](dns/dojo.hosts) (مثل
`www.shopizer-online.com → 10.0.8.21`) ويُمرّر ما سواها إلى الأعلى.

```bash
make up LAB=dns          # أو: make dns   (تشغيل الخادم)
```

على جهاز المهاجم (في WAN أيضًا):

```bash
echo 'nameserver 10.0.8.53' | sudo tee /etc/resolv.conf
curl http://www.shopizer-online.com/                        # ← struts2 @ 10.0.8.21
```

**ملاحظة حول البطاقات:** يملك Vagrant البطاقة الأولى كشبكة إدارة NAT، فتظهر
بطاقات المعامل الثلاث باسم `enp0s8/enp0s9/enp0s10` لا `enp0s3/enp0s8/enp0s9`.
يُثبّت ملف Vagrantfile عنوان MAC لكل بطاقة، ويستخدم المُهيّئ هذه العناوين
لإسناد عناوين `.250` تلقائيًا — فلا يهمّ ترتيب البطاقات الغامض إطلاقًا.

## التشغيل اليدوي (داخل الجهاز)

إن كنت **على مضيف Ubuntu** مباشرة (أو داخل الجهاز)، نفّذ من جذر المستودع:

```bash
sudo make install-deps                    # مرة لكل مضيف: docker + seccomp + compose + make
sudo make net                             # بطاقات ثابتة + promisc + شبكات macvlan
make up LAB=activemq                      # تشغيل معمل بعينه
make health                               # صحة الحاويات والشبكات والمسارات
make smoke                                # فحص النقاط الطرفية من داخل القطاعات
make down                                 # إيقاف (make reset يمحو الأحجام)
```

> البناء بأمر واحد عبر Vagrant/`install.sh` يُشغّل **كل شيء** دفعة واحدة، لذا
> امنح الجهاز ذاكرة كافية (`KAGE_MEMORY`) أو هيّئ بـ `KAGE_START=none` وشغّل
> المعامل درسًا درسًا. معمل `polkit` يُشغّل جهاز Ubuntu كاملًا داخل الحاوية
> (بطيء الإقلاع ويحتاج ~2GB)، وminio يشغّل ثلاث عُقد، وعدة معامل ثقيلة على JVM.

## ملاحظات السلامة

- **خذ لقطة (snapshot) لجهاز VirtualBox قبل كل حصّة وارجع إليها بعدها.** هذه
  خدمات مصابة عمدًا على قطاعات محاكاة.
- معمل **`polkit` ثقيل** (~2GB وإقلاع بطيء)، ورفع الصلاحية (PwnKit) **يمنح
  الجذر داخل جهازه** بالتصميم؛ عُدّ المعمل المُستغَلّ مُستهلَكًا للجلسة.
- نماذج الاستمرارية تترك آثارًا عمدًا (حسابات، مفاتيح، وحدات، cron، أصداف ويب)؛
  يعيد `make reset` أي معمل إلى حالة نظيفة.
- أبقِ الميدان على شبكة VirtualBox NAT معزولة فقط.
